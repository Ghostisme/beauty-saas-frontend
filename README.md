# 余乐圈美业前端

React + TypeScript + Vite + Ant Design，使用 pnpm 管理依赖。当前实现平台 / 企业独立登录、平台开通企业与企业管理员、跨企业管理视图，以及企业首页、设置、用户 / 部门 / 房间 / 角色权限管理、订单管理和短信管理，使用 Ant Design 默认蓝色主题。

## 本地启动

环境：Node.js 22.13+（本机已验证 24.6.0），pnpm 11.23.0。项目通过 `packageManager` 固定 pnpm 版本，所有直接依赖及 `pnpm-lock.yaml` 一并固定。

```powershell
cd "D:\github_code\余乐圈美业项目资料\beauty-saas-frontend"
pnpm install --frozen-lockfile
pnpm dev
```

- PC：<http://localhost:5173>
- 手机 / Pad：与电脑连接同一局域网，访问 `http://电脑局域网IP:5173`。本次机器地址为 `192.168.1.5`，地址变化后以 Vite 终端的 Network 地址为准。
- 局域网访问需在后端 `CORS_ALLOWED_ORIGINS` 中包含 `http://电脑局域网IP:5173`（本机已配置）。这是明确的来源白名单，不使用通配符；详见后端 `.env.example`。
- 后端：<http://127.0.0.1:8080>，Vite 将 `/api` 请求代理给后端。
- 独立联调时可在启动 Vite 的终端设置 `BEAUTY_API_PROXY_TARGET`，仅改变该 Vite 进程的后端目标；不设置时仍为本机 8080，日常使用不需要修改。
- 本机已有其他应用占用 3000、3001，因此使用 5173 并开启 `strictPort`，端口冲突会明确报错。
- 登录通过真实 `POST /api/user/login` 完成，分“平台登录”和“企业登录”。**原有 `admin` 为平台超级管理员，原密码不变**：使用默认的“平台登录”，只填写账号和密码，不填企业编码。
- 企业管理员由平台独立开通。负责人选择“企业登录”，填写平台分配的企业编码、账号、密码，不能使用平台身份查看其他企业。
- 账号区域明确区分“平台超级管理员”与企业身份。不含 `platformAdmin` 的旧会话缓存失效，升级后重新登录；平台管理员不再显示为 `yulequan` 的企业负责人。

安装依赖前请先在前端终端按 Ctrl+C 停止 Vite。Windows 正在运行的原生依赖可能被占用，引发 EPERM。日常使用锁文件安装即可，无需删除锁文件、反复强制安装或切换 npm。

## 当前功能

- 登录页：平台 / 企业入口分离，平台不填企业编码；企业编码、账号密码校验、提交状态、服务错误提示、密码显示 / 隐藏、忘记密码提示。
- 会话：持久化登录、过期检查、受保护路由、退出、跨标签页退出同步；损坏的本地缓存不会导致白屏。
- 布局：白色顶栏，只保留设置和登录信息。平台侧栏为“企业管理 / 用户管理”，默认进入企业管理；企业侧栏保留“首页”，并按账号权限显示“用户管理”。新增“顾客经营”标题分组，分组下按权限显示“订单管理”；未加入预约、开单、顾客等尚未实现的菜单。
- 显示模式：左下角按钮显示当前“电脑模式 / PAD模式”，点击即可互相切换。电脑模式铺满浏览器宽度，保留完整侧栏；PAD 模式按最大 1024px 的平板宽度居中展示，使用图标侧栏、重新排列的筛选区和较大的触控控件，不通过缩放整页模拟。切换不重置当前筛选条件，刷新后记住已选模式。
- 响应式：未手动选择模式时，按窗口宽度自动选择电脑 / PAD 布局；小于 768px 时始终优先使用手机抽屉导航、横向滚动提醒条和两列指标，窗口变宽后恢复已选模式。首页目标区和业绩区弹性填满可用视口高度，页脚靠底；低高度窗口减少留白，内容放不下时自然滚动，不裁切或压缩文字。
- 首页：提醒条、本月目标、“门店 / 我的”切换、业绩概览、今天 / 近7天 / 近30天 / 自定义日期、门店筛选控件。
- 首页提醒弹窗：顾客生日、待确认预约、持卡未到店、会员卡到期、充值提醒，独立表头 / 列表组件和蓝色空状态；支持关闭按钮、Escape、遮罩关闭、焦点返回原入口，小屏表格内部横向滚动，空状态始终居中。
- 设置：当前浏览器内的门店显示名称、登录账号与用户编号。

范围边界：短信发送 / 登录、提醒查询、目标和业绩统计接口尚未实现。顾客回访提醒、库存预警仍提示未开通；五个提醒已完成前端列表弹窗，尚无对应后端业务模块和数据，当前展示空状态，不伪造顾客、会员卡或预约记录。目标展示空状态，六项业绩数值是零值占位。日期切换和范围选择可交互。门店显示名称是当前浏览器**按租户隔离**的本地偏好；企业名称通过用户管理页面保存到后端。

### 平台企业管理

平台超管入口为侧栏“企业管理”，路由 `/platform/tenants`。企业账号即使直接输入地址，也不能访问平台页面和接口。

- **开通企业**：填写唯一企业编码、名称及新企业管理员的账号、姓名、初始密码；默认管理员账号为 `admin`，可自定义。保存后在后端事务中创建企业、独立账号和角色关系。
- **已有企业开通管理员**：原 `yulequan` 企业保留，但原负责人已提升为平台账号，所以显示“待开通管理员”；点击该企业的“开通管理员”为它单独创建负责人，不复制平台账号或密码。
- **管理员与企业维护**：编辑企业名称、启用 / 停用企业、重置企业管理员密码；重置或停用都会撤销相关旧登录。页面不回显密码。
- **真实概览**：企业、企业用户、部门 / 门店、房间数量，以及分页搜索 / 状态筛选；平台账号不是企业员工，不计入企业用户数量。
- **平台用户管理**：默认“全部企业 · 平台视图”，汇总用户、部门 / 门店、房间、角色，逐行标记所属企业，包含停用企业数据。选中一家企业或点击“管理企业数据”后进入该企业的五个管理页签。
- **数据范围**：只有平台的指定企业请求才添加 `X-Tenant-Id`，由组件作用域绑定，不使用可被其他页签覆盖的全局可变租户变量。自己改密 / 获取个人资料仍使用平台身份，不会切换为企业负责人。
- 快速切换页签和企业时合并当前浏览器 URL 参数；切换企业销毁旧表单、终止旧请求，避免旧企业结果覆盖新范围。

### 企业与用户管理

入口为侧栏“用户管理”，路由 `/user-management`，五个页签均通过真实 `/api/iam` 接口读写，不使用本地数组模拟保存。

| 页签 | 功能 |
| --- | --- |
| 用户 | 分页、搜索、部门和状态筛选；新建、编辑、删除、重置密码；多部门关联及“角色 + 门店范围”授权 |
| 部门 / 门店 | 组织树、上级选择、类型、排序、停用 / 启用与删除；服务端阻止环及有依赖的删除 |
| 房间 | 分页、搜索、部门筛选；所属部门、容量、状态、备注的维护；仅显示有权维护的门店 |
| 角色权限 | 管理员、店长、主理人、前台、美容师、员工、顾客七种内置身份，自定义角色及模块授权；维护权限自动包含查看 |
| 企业信息 | 当前租户 ID、企业编码、负责人、企业名称；仅名称可编辑，企业创建由平台完成 |

- 企业负责人不能在普通用户管理中被停用、删除、重置密码或移除管理员身份；自己改密使用顶部账号菜单。**平台超管可以在企业管理中重置该企业管理员密码**。
- 顶部“修改密码”已接真实接口，成功后退出并重新登录；用户列表重置密码使该账号旧登录失效。
- 设置菜单中的门店、房间、系统权限、授权管理、员工、职位入口已连接对应页签，其他业务入口保持后续实现。
- 接口检查 JWT 和服务器权限。前端只隐藏无权菜单 / 按钮，并不能替代后端鉴权；企业管理员不能开通或查看其他企业。
- 改变企业/账号时销毁旧表单与请求数据；迟到的请求不能覆盖新会话，不会因为旧会话的 401 退出新账号。
- 组织与房间在独立表维护；用户、角色、部门通过关系表关联。**后端不使用数据库外键**，事务和业务规则校验关系。
- PC 保留全宽布局，PAD 保留现有平板画布，手机使用抽屉导航；宽表格内部横向滚动，表单单列布局并在弹窗内滚动。

旧版本缺少租户 / 平台身份的缓存不能继续使用，升级后需要重新登录。平台开通脚本只是可信服务端自动化的可选通道，日常开通企业直接使用平台页面；无外键数据模型、V1 → V3 迁移及接口说明见后端仓库 README。

### 订单管理

入口为侧栏 **顾客经营 → 订单管理**，路由 `/orders`。沿用 Ant Design 默认蓝色，不使用参考图的粉色。

| 页签 | 当前实现 |
| --- | --- |
| 订单列表 | 顾客 / 订单 / 员工搜索，日期与消费门店筛选；截图中的 15 种消费类型、24 种支付方式和核对状态；订单编号 / 时间排序及服务端分页 |
| 未完成订单列表 | 顾客搜索、日期（默认今天）与消费门店筛选；挂单编号、时间、内容、服务人员、挂单合计；独立分页与空状态 |
| 尾款单 | 顾客、日期、门店查询；显示已确认且仍有未结算金额的订单，列表同时展示订单合计与尾款 |

- 共用表头结构及蓝色“暂无相关数据”空状态，显示实际查询记录数。宽表格在内部横向滚动，空状态不随表格横向偏移；加载失败明确提示并可重试，不伪装为空数据。
- 订单详情从真实接口读取顾客、消费门店、项目 / 产品明细、服务人员、支付明细和待收尾款。金额由后端以两位小数字符串返回，前端不使用浮点计算。
- 订单核对设置：启用 / 禁用，以及“已核对的订单，重新分配订单业绩后需重新核对”。设置按企业保存到数据库；取消不保存，重新打开重新读取；发生并发版本冲突时显示错误并支持重新加载。
- 授权员工可核对 / 取消核对已确认订单。禁用核对时不显示核对操作；挂单不能核对。维护请求带版本号，后端事务与审计日志记录实际操作。
- 平台默认汇总所有企业订单，逐行标识所属企业。**先选择企业，再修改该企业核对设置**；汇总列表的订单核对直接绑定订单所属租户，不使用全局可变租户变量。企业账号只有本企业数据，门店角色进一步限制门店范围。
- 新权限为 `orders:read/write` 和 `order-settings:read/write`。企业管理员自动拥有；其他员工需在“用户管理 → 角色权限”授权。核对设置是企业级权限，不能作为单店授权。
- 页签通过 URL `tab=all/pending/balance` 切换；平台选择使用 `tenantId`。各页签保留自己的筛选条件，切换企业清空旧表单和查询缓存，迟到请求不会覆盖新范围。
- PC 全宽、PAD 最大 1024px 居中重新排版、手机单列筛选及抽屉导航。弹窗低高度内部滚动，关闭后焦点回到入口，日期弹层支持窄屏 / 横屏。

**本轮范围边界：** 不提供开单、项目 / 产品主数据、会员卡销售、支付网关、退款执行、业绩重新分配页面。图片中的消费 / 支付项目前是订单查询维度，不代表这些业务操作已上线。后端已建订单、明细、人员、支付快照和核对设置表，但迁移不插入模拟订单。没有业务订单时列表自然为空；后续开单模块应在事务中校验同租户关联并写入这些表，业绩重新分配时递增订单 `performance_version` 与 `version`。

管理测试位于 `tests/user-management.spec.ts`、`tests/platform.spec.ts`、`tests/orders.spec.ts`、`tests/sms.spec.ts`，身份和接口夹具在 `tests/fixtures/`，不会被生产入口引用或写入业务库。浏览器夹具验证交互和请求契约；服务端租户隔离、真实事务及权限检查由后端集成测试和独立 MySQL 联调验证。

### 短信模块（V4）

左侧“拓客工具 → 短信”，页面路径 `/sms`，使用 Ant Design 默认蓝色，按参考图保留三个页签和分组布局。PC 全宽、PAD 使用现有模式开关及紧凑布局、手机单列设置 / 套餐，宽表在自身区域滚动。

- **短信设置**：交易提醒 5 项、预约提醒 4 项、特殊日期提醒 1 项、合伙人相关 3 项。模板文字来自后端，变量原样展示。开关及规则保存到当前企业；请求成功后才更新开关，失败保留原值，版本冲突可重新加载。未配置时开启会先弹出配置，取消不写入。
- **预约提醒设置**：按截图使用紧凑弹窗，设置“提前 N 分钟发送”，默认 1 分钟，范围 1–4320；确定后回显规则。单独修改规则不改变通知开关。
- **生日短信提醒设置**：默认提前 1 天，范围 0–30 天，0 表示当天发送；“自定义到店福利”默认关闭，使用“到店可享受生日权益”。开启后编辑到店时间说明和生日权益，关闭会保留已填写内容，再次开启可继续编辑；取消后恢复上次保存状态。旧版本已保存的自定义文案自动回显为开启。截图未提供每日发送时刻控件，界面不额外增加；接口保留已有时刻，新配置默认北京时间 09:00，实际发送服务待接入。
- **短信发送记录**：手机号搜索、默认本月日期范围、服务端分页、刷新、真实空状态 / 错误重试。下载报表为当前筛选条件下的全部记录，不仅是当前页，最多 5000 条；后端负责鉴权、UTF-8 CSV 与公式转义。下载请求带 JWT / 明确企业范围，并支持超时与页面切换取消。
- **短信余额充值**：后端真实余额，截图中五档套餐；点击套餐仅选中，蓝色边框 / 浅蓝底高亮，右下角显示对应金额及“立即支付”，更换套餐同步更新金额。点击“立即支付”才打开确认弹窗，取消保留选中状态；确认后仅创建待支付订单，重复请求使用相同幂等键。可查看分页充值历史和取消待支付单。当前未接入收款通道，**不会实际扣款、增加短信余额或伪造支付成功**；套餐价格是截图预设，后续再由服务商方案确定。
- 平台账号默认汇总视图，选择具体企业后维护设置或创建充值单；切换企业销毁旧表单与查询，请求始终绑定发起时的企业。企业账号仅查本企业数据。查看、设置维护、记录导出和充值管理分别由后端企业级权限控制；只读账号看不到导出按钮，不能切换设置或创建订单。
- 页签通过 `tab=settings/records/billing` 进入，平台企业范围通过 `tenantId`。短信服务商 / 支付网关后续接入；当前不调度短信，也未将订单、预约、会员卡事件接到发送链路。

主要文件：`src/pages/SmsPage.tsx`、`src/components/sms/`、`src/api/sms.ts`、`src/types/sms.ts`、`src/styles/sms.css`。交互与请求契约测试为 `tests/sms.spec.ts`，夹具位于 `tests/fixtures/sms.ts`，不在生产入口引用，也不会写入业务库。真实 MySQL / 浏览器联调材料保存在本地忽略目录 `artifacts/sms-live-*`。

```text
├── api/                        # 登录、企业身份管理、订单与短信接口
├── components/                 # 顶栏、侧栏、设置、iam 管理面板、订单弹窗、提醒组件
├── config/app.ts               # 产品名和默认门店名称

├── types/                      # 登录、身份管理、订单与提醒记录契约
├── App.tsx                     # 路由与保护
└── main.tsx                    # 应用入口与 Ant Design 配置
```
